# SETTINGS — 설정 창 및 JSON 저장 명세

## 1. UX 요구사항

메인 화면의 톱니바퀴 버튼에서 **설정 창 한 개**를 연다. 별도 계정/브라우저 로그인 설정 화면은 만들지 않는다.

### 필수 설정 항목

| JSON 키 | UI 명칭 | 타입/허용 값 | 기본값 |
|---|---|---|---|
| `schemaVersion` | 표시 없음 | 정수 | `1` |
| `downloadDirectory` | 다운로드 저장 위치 | 존재/생성 가능한 Windows 폴더 절대 경로 | 현재 사용자 `Downloads\Videos` |
| `quality` | 기본 화질 | `best`/`2160`/`1080`/`720` | `best` |
| `format` | 저장 형식 | `auto`/`mp4`/`mkv` | `auto` |
| `filename` | 파일 이름 | `title`/`title-id`/`date-title` | `title` |
| `concurrentDownloads` | 동시 다운로드 | 1~4 정수 | `2` |
| `retryCount` | 실패 재시도 | 0/1/3/5 | `3` |
| `browserAutoDetect` | 브라우저 영상 자동 감지 | boolean | `true` |
| `browserExtensionId` | 확장 ID | 빈 문자열 또는 `[a-p]{32}` | `""` |
| `completionNotification` | 다운로드 완료 알림 | boolean | `true` |

> 기본 경로는 고정된 `C:\Users\...` 문자열이 아니라 Windows 사용자 다운로드 위치를 실행 시 조회해 결정한다.

## 2. UI 구성

1. 일반: 다운로드 폴더 표시, [찾아보기] → **Windows 기본 폴더 선택 창**.
2. 다운로드: 화질·형식·파일명 규칙·동시 다운로드·재시도.
3. 브라우저/알림: 자동 감지 체크박스, 다운로드 완료 Windows 알림 체크박스.
4. Chrome 확장 프로그램: 설치 안내, 확장 ID, 호스트 등록, 연결 테스트, 연결 복구/재등록, 연결 해제 (동일 설정 창 안에 배치).
5. 하단: [저장], [취소], [기본값 복원]. [취소]는 미저장 변경을 버린다.

브라우저 자동 감지 설정은 확장과 동기화한다. 확장이 없는 상황에서는 데스크톱 값을 저장하고, 연결 후 동기화 상태를 보여준다. 연결/해제는 자동 실행이 아니라 사용자 명시 동작이다.

## 3. `settings.json` 스키마 예시

```json
{
  "schemaVersion": 1,
  "downloadDirectory": "D:\\Downloads\\Videos",
  "quality": "best",
  "format": "auto",
  "filename": "title",
  "concurrentDownloads": 2,
  "retryCount": 3,
  "browserAutoDetect": true,
  "browserExtensionId": "",
  "completionNotification": true
}
```

실제 다운로드 폴더 값은 예시이며 Windows 경로로 올바르게 파싱한다. `settings.json`에는 쿠키·토큰·로그인·비밀번호·사용자 계정 필드가 없다.

## 4. 로컬 저장 위치 정책

- 기본: 포터블 앱 폴더의 **`data/settings.json`**. 메인 실행 파일이 쓰기 가능한 경로에 있음을 확인한다.
- 앱 폴더가 쓰기 불가능할 때에는 임의로 설정을 유실시키지 말고 원인을 알리고 사용자가 쓰기 가능한 폴더에서 실행하도록 안내한다. 대체 폴더 지원은 추가 설계가 필요한 경우에만 결정한다.
- 최초 실행: 기본 설정을 동적으로 생성 → 유효성 검사 → 안전하게 파일 저장.
- 저장: 임시 파일 쓰기 → flush/sync 가능한 범위 수행 → 원자적 교체(Windows 제약 고려) → 결과 확인.
- 읽기/스키마 오류: 깨진 설정을 안전하게 백업하고 복구할 옵션/알림을 제공. 사용자 값 조용히 유실 금지.
- 알 수 없는 미래 스키마 버전은 임의 덮어쓰기하지 말고 명확하게 거부/마이그레이션 처리한다.
- 여러 창 또는 중복 앱 실행으로 인한 경합 저장을 방지한다.

## 5. 적용 시점

- 다운로드 폴더, 포맷, 화질, 재시도, 동시 제한은 **새 작업**부터 적용한다.
- 진행 중 다운로드의 경로나 포맷을 중간에 바꾸지 않는다.
- `browserAutoDetect` 및 완료 알림은 설정 저장 후 기능적으로 가능한 시점에 동기화한다.
- [기본값 복원]은 폼의 값을 바꾸는 작업이며 실제 영구 저장은 [저장] 클릭 시에만 한다.

## 6. 테스트 기준

- TC-01: 다운로드 폴더 변경 → 저장 → 앱 종료/재시작 → 설정 유지.
- TC-02: 없는 경로·쓰지 못하는 경로·상대경로 처리.
- TC-14: 잘못된 JSON·스키마 버전·손상된 파일에서 데이터 보존/복구.
- TC-15: 다운로드 중 설정 변경해도 기존 작업의 스냅샷 유지.
- 추가: 기본값 복원 뒤 취소하면 기존 값 보존, 저장 뒤 새로 열면 새 값 표시.

## 7. Chrome 확장 프로그램 영역 (v1.2)

설정 창 안에서 다음 항목을 제공한다. 상세 등록 계약은 `PACKAGING.md`, 수동 설치는 `BROWSER_EXTENSION.md`를 따른다.

| 표시/버튼 | 동작 |
|---|---|
| 확장 연결 상태 | 확인 필요 / 테스트 대기 / 연결됨 / 연결 끊김 / 실패. 마지막 성공 시각과 구분 |
| Native Messaging 등록 상태 | 미등록 / 등록됨·테스트 필요 / 경로 불일치 / ID 불일치 / 등록 실패 |
| 확장 ID 입력 | Chrome 확장 카드 또는 팝업에서 복사한 ID. 형식 검증 후 사용 |
| [확장 프로그램 설치 안내] | 설정 안에 순서를 표시하고 `extension/` 폴더 및 `chrome://extensions` 열기 시도 |
| [확장 폴더 열기], [Chrome 확장 관리 주소 복사] | 수동 로드 및 페이지 열기 실패 대안 |
| [호스트 등록] | 입력 ID를 저장하고 현재 경로 기반 매니페스트/HKCU 등록. ID 미입력 시 비활성 |
| [연결 테스트] | 사전 진단 후 30초간 확장 팝업의 테스트 요청을 기다림. 실제 왕복 성공만 인정 |
| [연결 복구/재등록] | 현재 ID/경로로 등록 교체 및 재테스트 안내 |
| [연결 해제] | 현재 복사본 소유의 HKCU 등록만 제거. Chrome 확장 수동 제거 안내 |

설치 안내에는 개발자 모드 활성화 → unpacked 로드 → 확장 ID 복사 → 호스트 등록 → 양쪽 연결 테스트를 명시한다. 웹스토어 강제 설치 버튼은 없다. EXE가 확장 설치 여부를 직접 알 수 없으면 `설치 확인 필요`로 표시한다.

`browserExtensionId`는 비밀값이 아닌 로컬 연결 설정이다. v1.1 설정에 키가 없으면 빈 문자열로 읽고 다음 저장 때 추가한다. 기존 설정 `schemaVersion: 1`은 유지하며 미래 버전 거부 규칙도 유지한다. HKCU 값·매니페스트 경로·현재 연결 상태·마지막 진단 결과를 설정 JSON의 참값으로 저장하지 않고 실행 시 조회한다.

[호스트 등록]/[연결 복구/재등록]은 즉시 실행하는 동작이다. 버튼 옆에 **“확장 ID 저장 및 Windows 사용자별 연결 등록을 즉시 변경합니다”**를 표시한다. 일반 옵션은 [저장] 때 적용하며 [취소]는 이미 실행한 등록/해제까지 되돌리지 않는다. ID 폼만 바꾸고 취소하면 등록은 바뀌지 않는다. ID 변경을 일반 [저장]으로 저장했다면 기존 연결을 무효화하고 `ID 변경·재등록 필요`로 표시한다. [기본값 복원]은 등록 해제나 allowlist 확대를 실행하지 않는다.

오류 안내는 관찰 가능한 근거에 한정한다. ID 불일치·호스트 미등록을 구별할 근거가 없으면 가능한 원인 목록으로 보여준다. 레지스트리가 있어도 실제 왕복이 없으면 `연결됨`으로 표시하지 않는다. 자동 감지 옵션을 켜는 것만으로 확장 설치·호스트 등록을 수행하지 않는다.

관련 검증: TC-16~20. 문서 v1.2는 UI/등록 구현 완료를 뜻하지 않는다.
