# PRD — 제품 요구사항 정의서

## 1. 제품 목표

**IDM의 브라우저 영상 자동 감지 사용 경험을 참고**하되 내부 코드를 복원하거나 복제하지 않고 독자적으로 구현한다. Chrome에서 사용자가 재생한 **인증이 필요하지 않은** 영상을 후보로 감지하고, 사용자가 클릭하면 Windows 프로그램이 분석·다운로드하여 지정된 폴더에 저장한다.

## 2. 대상과 시나리오

- 환경: Windows 11, Chrome 우선(Edge는 후속 확장 가능).
- 형태: 설치 의존성을 최소화한 **포터블 폴더 배포**. Chrome 연동을 위한 사용자별 Native Host 등록은 별도 필요.
- 사용자 흐름: 영상 페이지 열기 → 재생 → 확장 배지/팝업 후보 표시 → 다운로드 버튼 클릭 → 앱에서 포맷 분석 → 최고 화질 저장.
- 보조 흐름: 앱에서 직접 URL 입력 → 공개 영상 분석 → 다운로드.
- 감지는 자동이지만 **다운로드는 사용자의 명시 선택으로만 시작**한다.

## 3. 기능 요구사항

| ID | 우선순위 | 요구사항 | 수용 기준 |
|---|---|---|---|
| FR-01 | 필수 | Chrome MV3 확장으로 MP4/WebM/HLS/DASH 요청·HTML5 소스 탐지 | 공개 테스트 영상의 후보 표시 |
| FR-02 | 필수 | 탭별 영상 후보 중복 제거, 배지·팝업 표시 | 수많은 세그먼트가 각각 영상으로 표시되지 않음 |
| FR-03 | 필수 | 확장과 Windows 앱을 Native Messaging으로 연결 | 후보 데이터가 앱에 전달되고 연결 상태 확인 가능 |
| FR-04 | 필수 | 직접 URL 입력 및 yt-dlp 분석 | 실제 이용 가능한 포맷 표시 |
| FR-05 | 필수 | 최고 화질 기본 선택, 상한 화질 및 FFmpeg 병합 | 최고 품질/상한 정책에 맞게 저장, 재생 확인 |
| FR-06 | 필수 | 다운로드 큐, 진행률, 취소, 실패·재시도 | 사용자에게 상태·오류 표시 |
| FR-07 | 필수 | **설정 창 1개**, 저장 폴더 선택 및 옵션 저장 | 재실행 후 `settings.json`에서 복원 |
| FR-08 | 필수 | 설정 창 안내에 따른 개발자 모드 unpacked 로드, EXE의 HKCU 등록/해제/복구, ID allowlist | 일반 사용자 권한 최초 연결 및 폴더 이동·ID 변경 후 왕복 재검증 |
| FR-09 | 필수 | DRM/인증/미지원/만료 URL 상태에 대한 오류 안내 | 우회 없이 실패 사유 제시 |
| FR-10 | 선택 | 고급 감지 모드 타당성 조사 | 감지 누락 사례에 대한 전후 개선 확인 |

## 5. 범위 밖

회원가입, 로그인 화면, 사이트 로그인 연동, 쿠키·토큰·인증 세션 활용, DRM 복호화/우회, 일반 파일 다운로드 매니저, 토렌트, 화면 녹화, 영상 편집, 클라우드/서버, 사용자 DB/SQLite, 자동 유료 API 및 자동 영상 다운로드는 구현하지 않는다.

## 6. 비기능 요구사항

- **안정성:** 설정 손상 시 앱 종료 없이 복구 가능, 실패한 작업이 다른 작업을 중단시키지 않음.
- **보안:** 계정 정보 수집 없음, 외부 명령 인자 전달·URL·경로 검증, 원본 URL 및 쿼리값 로그 마스킹.
- **유지보수:** 확장·Native Host·데스크톱·다운로드 엔진 모듈 분리, 통신 버전 명시.
- **데이터:** 로컬 JSON. 데이터는 앱 폴더의 쓰기 가능 위치 우선, 비쓰기 가능 위치에서는 사용자에게 안내.
- **표현 정확성:** 감지된 영상 ≠ 다운로드 가능 영상; 확인 전 해상도는 `미확인`으로 표기.

## 7. 릴리스 수용 조건

실제 Windows 11 및 Chrome에서 **공개 MP4 1건 + 공개 HLS 1건 + 공개 DASH 1건**에 대해 감지→선택→앱 전달→저장→재생 확인을 수행한다. 설정을 변경한 뒤 재실행하여 값이 유지됨을 확인한다. 실패 사례(로그인 필요/DRM/주소 만료)를 정상적으로 알리며 자격 증명 우회 시도가 없어야 한다. 포터블 경로 이동과 연결 재설정이 작동해야 한다. 지원 범위 밖인 사이트는 지원 가능하다고 표기하지 않는다.

## 8. Chrome 설치 인수 기준 (v1.2)

EXE 설정 창 하나에서 설치 순서·확장 폴더·관리 주소·ID 입력·호스트 등록·연결 테스트·복구를 제공한다. 사용자가 Chrome 개발자 모드에서 직접 unpacked 확장을 로드하며, EXE가 HKCU에 현재 경로와 정확한 ID를 등록한다. 레지스트리 존재만으로 연결 성공을 표시하지 않는다. 이동 후 호스트 재등록과 필요 시 확장 재로드/ID 갱신으로 복구해야 한다. 웹스토어 강제 설치와 기업 정책 변경은 범위 밖이다. TC-16~20 결과를 릴리스 증거에 포함한다.
