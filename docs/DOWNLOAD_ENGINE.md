# DOWNLOAD_ENGINE — yt-dlp/FFmpeg 다운로드 설계

## 1. 목표

공개 페이지 URL 또는 Chrome에서 감지한 공개 미디어 URL을 분석하고, 가능한 범위에서 **실제로 이용 가능한 최고 화질**의 영상·음성을 저장한다. 다운로드는 Windows 프로그램이 전담한다.

## 2. 분석 전략

1. 사용자 선택 시 페이지 URL을 먼저 분석한다. yt-dlp의 사이트별 공개 추출기에서 포맷을 확인할 수 있는 경우 이를 우선한다.
2. 지원 불가/포맷 없음이면 **인증 불필요한** 감지 미디어 URL을 대체 경로로 분석한다.
3. HLS `.m3u8`, DASH `.mpd`는 포맷 변형과 오디오·비디오의 분리 여부를 확인한다.
4. `blob:` 주소는 직접 다운로드 URL로 사용하지 않는다.
5. 인증 필요/만료/DRM/지원 불가/네트워크 오류를 구분하려 노력하되, 판단 불확실 시 `원인 미확인`으로 표시한다.
6. 분석 실패가 나도 Chrome의 쿠키/세션/토큰을 추가로 가져오거나 무단으로 보호를 우회하지 않는다.

## 3. 화질·형식 정책

| 옵션 | 기본값 | 동작 |
|---|---|---|
| `quality` | `best` | 가능한 최상 화질 영상+오디오 선택 |
| `quality=2160` | - | 최대 높이 2160p 중 최상 선택 |
| `quality=1080` | - | 최대 높이 1080p 중 최상 선택 |
| `quality=720` | - | 최대 높이 720p 중 최상 선택 |
| `format` | `auto` | 품질 보전/호환 가능한 원래 스트림·컨테이너 우선 |
| `format=mp4` | - | 가능한 경우 MP4 병합 우선, 무조건 재인코딩하지 않음 |
| `format=mkv` | - | 가능한 경우 MKV 병합 우선 |

- 설정한 높이와 정확히 일치하는 포맷이 없으면 상한 이하의 최고 가용 포맷을 선택하고 실제 높이를 표시한다. 상한 이하로 확인된 영상 포맷이 없으면 이유를 표시한다. 해상도가 보고되지 않은 포맷은 최고 화질 설정에서 사용할 수 있다.
- 별도 오디오가 있는 경우 yt-dlp 및 FFmpeg로 병합한다. 단순 병합 불가능 시 사용자에게 알리고 과도한 재인코딩을 기본 동작으로 하지 않는다.
- 접근 가능한 가장 좋은 스트림이 `1080p`라면 `4K`를 선택했더라도 `1080p`로 저장하고 명시한다.
- 무조건 MP4 출력이 가능한 것처럼 UI에서 약속하지 않는다.

## 4. 작업 상태 머신

```text
queued → analyzing → downloading → [merging] → completed
   └───────────────────────────────────→ failed
                       ↘ cancelled
                       ↘ paused → downloading   (실제로 지원될 때만)
```

- 각 작업은 고유 `jobId`와 **시작 시점 설정 스냅샷**(폴더, 화질, 형식, 재시도 정책)을 가진다.
- 동시 다운로드 제한: 1~4(기본 2). 상한 초과 작업은 대기 큐에 남는다.
- 재시도: 0/1/3/5(기본 3), 일시적 네트워크 오류 등에만 적용. 인증/DRM/명백한 미지원에는 무한 재시도 금지.
- 사용자 취소는 자식 프로세스 종료 및 임시 파일 정리를 제어해야 한다. 다운로드 재개는 프로토콜·사이트·도구 기능에 따라 불가능할 수 있다.
- 정체·타임아웃·비정상 종료를 감지하고, 작업별 오류는 독립적으로 처리한다.

## 5. 외부 실행 파일

- yt-dlp, FFmpeg의 존재 및 버전을 실행 전에 확인한다.
- `std::process::Command` 등 **인자 배열** 방식으로 실행하고 셸 문자열/원격 입력을 명령으로 조합하지 않는다.
- 브라우저 쿠키를 읽는 `--cookies`, `--cookies-from-browser`, 인증용 임의 `Cookie`/`Authorization` 헤더 전달 옵션을 구현하지 않는다.
- 가능하면 JSON 메타데이터 출력을 파싱하고, 로그/진행률을 분리해 유지보수성을 확보한다.
- 파일 경로는 안전한 절대 경로 및 검증된 폴더만 사용하며 `file:`, `ftp:`, `javascript:`, localhost·사설망 등 예기치 않은 대상에 대한 요청을 제한한다.
- 다운로드용 네트워크 요청은 리다이렉트, 호스트·스킴 변경, DNS 결과 등 위험한 재해석 상황도 방어적으로 처리한다. 단순한 문자열 검사를 안전성 증명으로 가정하지 않는다.
- `yt-dlp` 기본 동작에 내재된 부가 기능과 포맷 후처리도 최소 권한·제한 범위로 제어한다.

## 6. 파일 저장

- `downloadDirectory` 아래에 저장한다. 파일명 규칙: `title`, `title-id`, `date-title`.
- Windows 금지 문자, 예약 이름, `..`, 경로 구분자, 지나치게 긴 이름을 정규화한다.
- 파일 충돌 시 기존 파일 덮어쓰기를 하지 않고 `(1)`, `(2)` 등 번호를 부여한다.
- 다운로드 도중에는 임시 파일 사용을 허용하고 완료된 파일만 사용자에게 완료로 표시한다.
- 로그에는 민감한 원본 URL 쿼리나 명령행 전체를 남기지 않는다. 오류 출력에서 URL·토큰 패턴을 마스킹한다.
- 다운로드 이력이 필요하면 `downloads.json`에 `jobId`, 제목, 저장 경로, 상태/시간 정도만 남긴다. **원본 URL과 인증 정보 영구 저장 금지**.

## 7. 테스트 기준

- 공개 MP4 다운로드 후 실제 파일 재생, 최고 품질/상한 화질 정책(TC-07).
- 공개 HLS 마스터와 DASH 분리 스트림 저장·병합(TC-04/05).
- 취소·실패·재시도·중복 파일명·읽기 전용 폴더·도구 미설치(TC-02/08/13).
- 로그인 필요/만료/DRM 관련 실패 시 자격 정보 재사용·우회 없이 종료(TC-10/11).
- 자동화 테스트에는 공개 테스트 자산 또는 모의 yt-dlp 출력 사용. 실제 사이트 동작은 별도 통합 검증한다.

공식 참조: https://github.com/yt-dlp/yt-dlp/blob/master/README.md , https://ffmpeg.org/documentation.html

## 8. R4 분석 동작

- 실행 파일 옆 `tools/yt-dlp.exe`와 `tools/ffmpeg.exe`를 각각 검사한다. 최소 지원 버전은 yt-dlp 2025.11.12와 FFmpeg 6이다. 도구 설치는 사용자가 관리하며 FFmpeg 진단 상태와 별개로 yt-dlp가 준비되면 메타데이터를 분석할 수 있다.
- 공개 HTTP/HTTPS 기본 포트의 주소를 대상으로 yt-dlp 범용·HTML5 추출기를 사용한다. 모의 실행으로 첫 영상의 메타데이터를 읽으며 분석 시도당 30초를 제한한다. yt-dlp 설정 파일, 플러그인, JS 런타임, 원격 구성요소, 쿠키와 브라우저 세션을 사용하지 않는다. 사이트 전용 추출기와 영상 파일 저장은 분석에 포함되지 않는다.
- Chrome 후보는 페이지 주소를 먼저 분석한다. 페이지가 미지원이거나 포맷이 없으면 서로 다른 유효한 감지 주소를 한 번 시도한다. 인증 필요, 접근 거부, 만료, 보호 감지에서는 대체 주소를 시도하지 않는다.
- 루프백 프록시는 요청 대상 호스트·포트와 DNS 응답 전체를 검사하고 허용된 공인 IP에 직접 연결한다. HTTP 요청은 허용 목록의 헤더만 전달한다. HTTPS의 CONNECT는 암호화된 경로와 헤더를 검사할 수 없다. 입력 주소와 yt-dlp가 결과에 보고한 페이지·미디어·매니페스트 주소에는 별도로 URL 정책을 적용한다. UI로는 정규화한 메타데이터와 고정 오류 코드만 보낸다.
- 인증 필요, 만료·제거, 접근 거부, DRM 보호·의심, 미지원, 네트워크 장애를 확인된 신호에 따라 구분한다. 403은 원인이 명시되지 않으면 접근 거부로 표시한다. 보호가 확인되거나 의심되는 포맷은 목록에서 제외한다. 혼합 응답에서 분석 가능한 영상 포맷이 남으면 제외한 포맷 수를 표시한다.

## 9. R5 전송 및 병합

- 분석 후 다운로드를 요청하면 공개 주소를 다시 확인한다. 독립 파일을 전송할 때는 허용된 포맷의 주소와 최소 메타데이터만 yt-dlp 표준 입력에 전달한다. 추출기가 보고한 헤더와 원본 JSON은 전달하지 않는다.
- 각 스트림 전송의 시간 한도는 10분이며 프록시 한도는 2 GiB이다. yt-dlp가 보고한 바이트·속도를 표시하고 전체 크기를 알 수 없으면 수신 바이트를 표시한다.
- FFmpeg는 작업 폴더의 검증된 미디어 입력만 읽고 스트림을 복사한다. 자동 형식은 같은 계열 스트림의 원래 컨테이너를 우선하고 분리 스트림의 계열이 다르면 MKV를 사용한다. 명시한 MP4에 적합한 소스나 오디오가 없거나 병합이 실패하면 오류를 표시한다. MKV를 지정하면 Matroska에 복사한다.
- 작업은 설정 스냅샷과 함께 앱 메모리에서 관리한다. 일시정지와 취소는 진행 중인 자식 프로세스를 종료하고 임시 파일을 정리한다. 일시정지 후에는 같은 작업을 처음부터 다시 실행한다. 원격 파일이 동일하다는 보장이 필요한 바이트 단위 이어받기는 제공 범위 밖이다. 일시적 네트워크 오류와 시간 초과만 설정 횟수만큼 자동 재시도하며, 한도를 소진한 작업은 사용자가 다시 시도할 수 있다.
- 완료 파일은 설정 폴더 안의 임시 디렉터리에서 검증한 뒤 기존 파일을 교체하지 않는 이동으로 게시한다. 이름은 제목, 제목과 쿼리를 뺀 공개 주소의 짧은 해시, 현지 날짜와 제목 중 설정한 형식을 사용한다. 같은 이름이 있으면 숫자 접미사를 붙인다.
- 실행 중인 작업 수에는 분석·전송·파일 처리·재시도 대기가 포함된다. 1~4개 상한을 낮추면 기존 작업은 마무리되고 새 작업은 슬롯을 기다린다. 완료 알림이 켜진 작업이 파일을 저장하면 Windows Shell에 알림을 요청한다. Windows의 알림 및 집중 모드가 표시를 결정한다. [Windows Shell 알림 API](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shell_notifyiconw)

## 10. R6 세그먼트 전송

- HLS는 yt-dlp가 보고한 화질을 선택하고 마스터에서 그 영상 변형에 지정된 오디오 그룹의 기본 트랙을 우선한다. 종료된 공개 재생목록의 fMP4 초기화 조각, MPEG-TS, AAC 및 바이트 범위를 처리한다. 암호화 선언, 라이브, 불연속, 초기화 조각 교체는 오류로 표시한다. [HLS 규격](https://www.rfc-editor.org/rfc/rfc8216)
- 세그먼트 전송은 Rust HTTP 클라이언트에서 수행한다. 매니페스트와 조각 주소, 리디렉션을 검증하고 공인 IP만 통과하는 기존 프록시를 사용한다. 바이트 범위 응답은 서버가 요청 범위를 그대로 반환해야 한다. 실패한 조각을 건너뛰지 않으며 FFmpeg에는 로컬 임시 파일만 전달한다.
- DASH는 단일 기간의 정적 MPD와 yt-dlp가 순서대로 확인한 초기화·미디어 조각을 사용한다. 같은 매니페스트에서 영상과 음성을 선택해 병합한다. 보호 선언, 동적·다중 기간 MPD, 외부 링크, 조각 범위가 필요한 매니페스트는 이 전송 경로에서 지원 범위를 벗어난다. 독립 파일로 제공되는 DASH 형식은 기존 전송 경로를 사용한다.
