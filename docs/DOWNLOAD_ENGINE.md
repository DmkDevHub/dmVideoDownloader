# DOWNLOAD_ENGINE — yt-dlp/FFmpeg 다운로드 설계

## 1. 목표

공개 페이지 URL 또는 Chrome에서 감지한 공개 미디어 URL을 분석하고, 가능한 범위에서 **실제로 이용 가능한 최고 화질**의 영상·음성을 저장한다. 다운로드는 Windows 프로그램이 전담한다.

## 2. 분석 전략

1. 사용자 선택 시 페이지 URL을 먼저 분석한다. yt-dlp의 사이트별 공개 추출기에서 포맷을 확인할 수 있는 경우 이를 우선한다.
2. 지원 불가/포맷 없음이면 **인증 불필요한** 감지 미디어 URL을 대체 경로로 분석한다.
3. HLS `.m3u8`, DASH `.mpd`는 포맷 변형과 오디오·비디오의 분리 여부를 확인한다.
4. `blob:` 주소는 직접 다운로드 URL로 사용하지 않는다.
5. 인증 필요/만료/DRM/지원 불가/네트워크 오류를 구분하려 노력하되, 판단 불확실 시 `원인 미확인`으로 표시한다.
6. 분석 실패가 나도 Chrome의 쿠키/세션/토큰을 추가로 가져오거나 무단으로 보호를 우회하지 않는다.

## 3. 화질·형식 정책

| 옵션 | 기본값 | 동작 |
|---|---|---|
| `quality` | `best` | 가능한 최상 화질 영상+오디오 선택 |
| `quality=2160` | - | 최대 높이 2160p 중 최상 선택 |
| `quality=1080` | - | 최대 높이 1080p 중 최상 선택 |
| `quality=720` | - | 최대 높이 720p 중 최상 선택 |
| `format` | `auto` | 품질 보전/호환 가능한 원래 스트림·컨테이너 우선 |
| `format=mp4` | - | 가능한 경우 MP4 병합 우선, 무조건 재인코딩하지 않음 |
| `format=mkv` | - | 가능한 경우 MKV 병합 우선 |

- 상한 화질이 없을 경우 정책에 맞는 **최고 가용 포맷**으로 떨어지되 실제 선택된 해상도를 표시한다.
- 별도 오디오가 있는 경우 yt-dlp 및 FFmpeg로 병합한다. 단순 병합 불가능 시 사용자에게 알리고 과도한 재인코딩을 기본 동작으로 하지 않는다.
- 접근 가능한 가장 좋은 스트림이 `1080p`라면 `4K`를 선택했더라도 `1080p`로 저장하고 명시한다.
- 무조건 MP4 출력이 가능한 것처럼 UI에서 약속하지 않는다.

## 4. 작업 상태 머신

```text
queued → analyzing → downloading → [merging] → completed
   └───────────────────────────────────→ failed
                       ↘ cancelled
                       ↘ paused → downloading   (실제로 지원될 때만)
```

- 각 작업은 고유 `jobId`와 **시작 시점 설정 스냅샷**(폴더, 화질, 형식, 재시도 정책)을 가진다.
- 동시 다운로드 제한: 1~4(기본 2). 상한 초과 작업은 대기 큐에 남는다.
- 재시도: 0/1/3/5(기본 3), 일시적 네트워크 오류 등에만 적용. 인증/DRM/명백한 미지원에는 무한 재시도 금지.
- 사용자 취소는 자식 프로세스 종료 및 임시 파일 정리를 제어해야 한다. 다운로드 재개는 프로토콜·사이트·도구 기능에 따라 불가능할 수 있다.
- 정체·타임아웃·비정상 종료를 감지하고, 작업별 오류는 독립적으로 처리한다.

## 5. 외부 실행 파일

- yt-dlp, FFmpeg의 존재 및 버전을 실행 전에 확인한다.
- `std::process::Command` 등 **인자 배열** 방식으로 실행하고 셸 문자열/원격 입력을 명령으로 조합하지 않는다.
- 브라우저 쿠키를 읽는 `--cookies`, `--cookies-from-browser`, 인증용 임의 `Cookie`/`Authorization` 헤더 전달 옵션을 구현하지 않는다.
- 가능하면 JSON 메타데이터 출력을 파싱하고, 로그/진행률을 분리해 유지보수성을 확보한다.
- 파일 경로는 안전한 절대 경로 및 검증된 폴더만 사용하며 `file:`, `ftp:`, `javascript:`, localhost·사설망 등 예기치 않은 대상에 대한 요청을 제한한다.
- 다운로드용 네트워크 요청은 리다이렉트, 호스트·스킴 변경, DNS 결과 등 위험한 재해석 상황도 방어적으로 처리한다. 단순한 문자열 검사를 안전성 증명으로 가정하지 않는다.
- `yt-dlp` 기본 동작에 내재된 부가 기능과 포맷 후처리도 최소 권한·제한 범위로 제어한다.

## 6. 파일 저장

- `downloadDirectory` 아래에 저장한다. 파일명 규칙: `title`, `title-id`, `date-title`.
- Windows 금지 문자, 예약 이름, `..`, 경로 구분자, 지나치게 긴 이름을 정규화한다.
- 파일 충돌 시 기존 파일 덮어쓰기를 하지 않고 `(1)`, `(2)` 등 번호를 부여한다.
- 다운로드 도중에는 임시 파일 사용을 허용하고 완료된 파일만 사용자에게 완료로 표시한다.
- 로그에는 민감한 원본 URL 쿼리나 명령행 전체를 남기지 않는다. 오류 출력에서 URL·토큰 패턴을 마스킹한다.
- 다운로드 이력이 필요하면 `downloads.json`에 `jobId`, 제목, 저장 경로, 상태/시간 정도만 남긴다. **원본 URL과 인증 정보 영구 저장 금지**.

## 7. 테스트 기준

- 공개 MP4 다운로드 후 실제 파일 재생, 최고 품질/상한 화질 정책(TC-07).
- 공개 HLS 마스터와 DASH 분리 스트림 저장·병합(TC-04/05).
- 취소·실패·재시도·중복 파일명·읽기 전용 폴더·도구 미설치(TC-02/08/13).
- 로그인 필요/만료/DRM 관련 실패 시 자격 정보 재사용·우회 없이 종료(TC-10/11).
- 자동화 테스트에는 공개 테스트 자산 또는 모의 yt-dlp 출력 사용. 실제 사이트 동작은 별도 통합 검증한다.
