# SECURITY_SCOPE — 지원 범위·보안·개인정보

## 1. 명시적으로 구현하지 않는 기능

- 프로그램 자체 회원가입/로그인, 사용자 프로필, 인증 서버, 원격 계정 관리.
- 사이트 로그인 연동, 인증 세션 전달·복원·재사용.
- Chrome의 쿠키 저장소 읽기, `Cookie`·`Set-Cookie`·`Authorization` 요청/응답 헤더 수집, Bearer 토큰 추출/전달.
- yt-dlp의 `--cookies`, `--cookies-from-browser` 등으로 브라우저 로그인 정보를 전달하는 기능.
- DRM 복호화, 키 추출/다운로드, 우회 기능, 보호된 미디어를 녹화 등으로 대체 취득하는 기능.
- 서버·클라우드 동기화·텔레메트리·사용자 DB, 일반 파일 다운로더·영상 녹화기.

이 범위는 개발 편의를 위해 임의로 완화해서는 안 된다. 로그인 중인 웹페이지에서 요청이 **관찰**되는 것과 세션을 **재사용**하는 것은 다르다. 단순 감지는 가능해도 인증 필요 영상의 다운로드는 지원 대상 밖이다.

## 2. 안전한 다운로드 조건

- 사용자가 **명시적으로 선택한**, 인증 없이 접근 가능한 공개 미디어를 중심으로 한다.
- 다운로드 대상의 출처·라이선스 및 이용 조건은 사용자가 준수해야 하며, 프로그램은 DRM 회피나 접근 통제 우회 기능을 제공하지 않는다.
- URL의 쿼리 매개변수가 일회성 서명·토큰 등 자격 증명의 역할을 할 수 있으므로, 명백한 인증/액세스 토큰 내장 링크는 대상에서 제외한다. 모든 URL 구조를 완벽하게 판정할 수 있다는 주장은 금지한다.
- URL에 사용자 이름/비밀번호가 포함된 형태(`user:pass@host`)는 허용하지 않는다.
- URL 직접 입력과 브라우저 후보 모두 **데이터**로 취급하며 원격 입력을 명령으로 실행하지 않는다.

## 3. 브라우저 확장 최소 권한

- 필요할 때만 `webRequest`, `nativeMessaging`, 탭/사이트 접근 관련 권한을 요청한다.
- 인증정보를 읽기 위한 `cookies`, `webRequest`의 전체 민감 헤더 수집, `debugger` 권한은 기본 버전에서 제외한다.
- 자동 감지는 사용자 브라우저의 네트워크를 감시하는 기능이므로 어떤 사이트 접근이 필요한지 설치 안내에서 투명하게 고지한다.
- 확장 자체에 추적·사용자 식별·서버 전송 로직을 넣지 않는다.

## 4. 네트워크/파일 경계

- `http:`/`https:` 외의 스킴과 사용자정보 포함 URL을 금지한다.
- `localhost`, loopback, link-local, RFC1918 사설주소, 메타데이터 서비스, `file:` 등의 내부 자원에 대한 요청을 차단할 방안을 설계하고 검증한다.
- 리다이렉트와 DNS 해석 시에도 이 경계를 유지하도록 방어하며, 미디어 도구의 하위 요청도 고려한다.
- 명령줄 인수로 URL/경로를 안전하게 전달하며 셸 삽입을 피한다.
- 다운로드 파일명 정규화 및 경로 순회 방지. 외부 데이터가 지정된 저장 폴더 밖의 파일을 덮어쓸 수 없도록 한다.
- Native Host 등록은 사용자별 HKCU, 정확한 확장 ID의 `allowed_origins`와 로컬 IPC 사용자별 접근 제어를 사용한다.
- 업데이터나 외부 바이너리 다운로드를 기본 자동 기능으로 넣지 않는다.

## 5. 저장·로그 원칙

- `settings.json`에는 비밀값/사용자 식별정보 없이 다운로드 선호와 비밀값이 아닌 확장 ID만 저장한다.
- 작업 이력은 필요할 때만 최소 정보로 저장한다. 원본 URL·민감한 쿼리·헤더 값은 영구 기록하지 않는다.
- yt-dlp/FFmpeg 표준 출력·표준 오류를 그대로 로그에 보관하면 URL이 유출될 수 있다. 원문 대신 에러 코드·정제된 메시지를 저장한다.
- Native Messaging의 메시지 전문, 페이지 제목, URL 등을 디버그 로그에 무조건 남기지 않는다.
- Chrome 후보 캐시는 현재 세션에서 필요한 최소 범위로 유지하고 탭 종료/이동 시 정리한다.

## 6. 실패·보호 감지 표기

- `인증 필요`는 로그인 세션 전달 요청을 뜻하지 않는다. 다운로드 불가 안내로 끝낸다.
- DRM 감지는 확정적으로 판정 가능한 범위로 제한하고, 불확실할 땐 `보호 또는 미지원 가능성`을 표시한다.
- 페이지가 브라우저에서 재생돼도 다운로드를 보장하지 않는다.
- 고급 디버거 모드가 필요하면 사용자에게 먼저 범위·권한·보안 영향을 알리고 별도 결정 항목으로 둔다.

## 7. 보안 검증 항목

- 확장 모델 및 IPC 메시지에 쿠키/토큰/인증 헤더 필드가 없는지 확인.
- 감지된 후보를 조작하여 `file:`, 내부 IP, 경로 순회, 비정상 길이·유효하지 않은 타입을 넣었을 때 거부.
- 로그, `settings.json`, `downloads.json`에서 원시 토큰/쿼리 문자열이 없는지 검사.
- 미등록 Host/잘못된 확장 ID/권한 없는 IPC 클라이언트 접근을 거절.
- 로그인 필요/DRM 테스트에서 우회나 인증정보 조회 호출이 발생하지 않는지 확인.

## 8. 설치·등록 경계 (v1.2)

- EXE는 안내와 사용자별 호스트 등록만 담당한다. Chrome 개발자 모드·확장 로드·제거는 사용자 조작이며 웹스토어 강제 설치·기업 정책·다른 앱 등록 변경을 하지 않는다.
- ID는 로컬 설치한 확장 카드/팝업에서 확인해 입력한다. 형식 검사 뒤 정확한 origin 한 개만 허용하며 새 ID는 기존 값을 대체한다. 통신 오류를 해결하려고 allowlist를 넓히지 않는다.
- Host가 받은 origin·로컬 IPC 접근 제어를 함께 검증한다. 확장 ID 검증은 사이트 인증 세션 수집 기능을 뜻하지 않는다.
- 폴더 이동 시 현재 경로로 명시적으로 재등록한다. 연결 해제는 현재 복사본 소유의 HKCU 키만 제거한다. 다른 복사본을 가리키는 키를 임의 삭제하지 않는다.
- EXE의 등록/복구 버튼은 즉시 적용되는 동작임을 표시한다. 사용자 프로필 파일을 분석해 확장 설치 상태를 추측하거나 거부된 확장의 요청으로 허용 ID를 추가하지 않는다.
- 연결 테스트는 제어 메시지만 사용하고 미디어 요청·자동 다운로드를 발생시키지 않는다. TC-17~20에 거부/복구 경계를 포함한다.
